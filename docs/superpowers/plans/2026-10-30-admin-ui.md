# Password-Protected Admin UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let an operator select a race from the terminal or a protected admin page and change YAML-backed dashboard settings without restarting the server.

**Architecture:** Keep `OPTIONS` and YAML parsing in `config.py`; serialize terminal, admin, and watcher updates through one application settings lock. Track a race generation so the server discards results from an old race and the browser resets race-specific state. Separate terminal input into `race_prompt.py` and admin routes/security into `admin.py`.

**Tech Stack:** Python 3.11, Flask/Jinja, pytest, existing browser JavaScript/CSS, ruamel.yaml for comment-preserving writes. Use Node's built-in test runner for dashboard JavaScript regression tests; no npm packages.

**Spec:** `docs/superpowers/specs/2026-10-29-admin-ui-design.md`

## Global Constraints

- Work in the existing isolated worktree and feature branch.
- `.env` / process environment provide secrets only: `WEBSCORER_API_ID`, `WEBSCORER_API_TOKEN`, `ADMIN_PASSWORD`. Non-secret options resolve from YAML, then defaults.
- The default file remains `config.yaml`; `--config <path>` selects the file for startup, watching, and writes. Relative `data_file` paths retain process-working-directory semantics.
- Start the web server alongside the interactive race prompt when no live WebScorer race is configured. No clock-based timeout; first valid startup selection wins.
- Skip the prompt for a saved race, file-backed input, or non-interactive stdin. Keep UI selection available where admin is enabled.
- Accept race IDs without a preflight results fetch. Clear the old race, show waiting, and retry failed results fetches on the normal cadence.
- Use a shared password, per-process random session key, constant-time comparison, CSRF, and admin security headers. Document trusted-LAN HTTP deployment; no TLS or user accounts.
- Preserve YAML comments and unknown non-secret keys. Validate before a same-directory atomic replacement.
- Keep supported options/defaults, README, startup output, and project rules consistent.
- Do not modify the committed config for demonstrations. Use temporary YAML and fixture data, then inspect the running app in a browser.
- Keep `start.sh` / `start.ps1` equivalent if either changes. This plan uses `python app.py --config ...` for custom configurations and does not require script changes.
- Commit logical increments with conventional messages and the trailer `Co-authored-by: Copilot App <223556219+Copilot@users.noreply.github.com>`.

## Review Focus

- An old poll finishes or fails after a race switch: neither outcome may restore the old race or its error.
- CLI and UI submit competing startup choices, or an operator submits a stale form: the losing request must not overwrite the accepted selection.
- UI selection cancels partially typed terminal input, or stdin reaches EOF: no blocked reader, later input consumption, or stopped web server.
- A file write fails or an editor changes YAML after form rendering: preserve the file and running settings; explain the failure.
- The browser receives waiting/error responses and overlapping fetches during a switch: discard stale responses and seed finish notifications from the first successful result set.

## File Structure and Shared Interfaces

| File | Responsibility |
|---|---|
| `config.py` | YAML-only option resolution, reusable validation, read snapshots/revisions, atomic writes, watcher |
| `app.py` | Active settings, serialized save/apply, race-generation cache protection, poll wakeups, CLI startup/server lifecycle |
| `race_prompt.py` (new) | Cancellable Windows/POSIX terminal line input, race-list prompt, console-log handoff |
| `admin.py` (new) | Login/session/CSRF, safe public form data, race-list endpoint, save requests |
| `templates/admin_login.html`, `templates/admin.html` (new) | Escaped login and settings forms |
| `static/admin.css`, `static/admin.js` (new) | Phone layout and provider-dependent race controls; no inline scripts/styles |
| `static/dashboard.js` | Waiting copy, race-generation resets, finish-notification baseline |
| `tests/test_config_store.py`, `tests/test_race_prompt.py`, `tests/test_admin.py` (new) | Persistence, terminal, and admin tests |
| `tests/dashboard.test.cjs` (new) | Real dashboard JavaScript in a stub DOM using `node:test` / `node:vm` |
| Existing config/app tests, README, `.env.example`, project rules, CI | Regression coverage and operator/developer guidance |

`ConfigValidationError(ConfigError)` exposes `errors: dict[str, str]`; `ConfigConflict(ConfigError)` signals an outdated file revision.

`read_config_snapshot(config_path: str, secrets: dict) -> tuple[dict, str]` returns resolved settings plus startup credentials and a SHA-256 revision of the same file bytes. `save_config(config_path: str, updates: dict, secrets: dict, *, expected_revision: str | None = None) -> dict` returns the saved resolved config.

`update_dashboard(app: Flask, updates: dict, *, expected_revision: str | None = None, startup_only: bool = False) -> bool` owns the shared settings lock, writes, and applies. `False` means another startup selector already chose a race; errors raise. Admin callers supply a revision; the CLI merges only `race_id` into the latest file.
